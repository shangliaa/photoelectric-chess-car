# K230 端识别与运动逻辑说明

> 版本：无舵机版（非阻塞流畅版）
> 帧率：约 29 FPS（640x480）

---

## 一、识别逻辑

### 1.1 颜色色块识别（vision.py）

每帧采图后，用 LAB 色彩空间的 `find_blobs` 找三类色块：

| 色块 | 阈值配置 | 用途 |
|------|---------|------|
| 红色棋子 | `RED_THRESHOLD` | 识别己方（或对方）红棋子 |
| 黑色棋子 | `BLACK_THRESHOLD` | 识别己方（或对方）黑棋子 |
| 球门区 | `GOAL_THRESHOLD` | 识别球门位置 |

己方颜色由 `config.MY_COLOR` 决定（默认 `red`）。

返回每个色块的 `x, y, w, h, cx, cy, area`（中心坐标+面积）。

### 1.2 棋子字符识别（vision_ocr.py）— 可选增强

在颜色找到棋子后，进一步识别棋子上的汉字（帅/将/车/马/炮/相/士/兵/卒），以获取分值。

**工作流程**：
1. 裁出棋子区域，收缩 15% 去掉圆形边缘
2. 转灰度 + 二值化（汉字深色，棋子底色浅）
3. 与 `/sdcard/templates/` 下的 `.pgm` 模板做 `find_template` 匹配（NCC）
4. 取最高分且超过 `OCR_MIN_CONFIDENCE` 的模板作为识别结果
5. 查 `PIECE_VALUES` 表得到分值

**无模板时**：`ocr.available == False`，自动跳过识字，回退到原策略。

### 1.3 分值表（config.py 的 PIECE_VALUES）

| 棋子 | 类型键 | 分值 |
|------|--------|------|
| 红帅 | `red_shuai` | 10 |

| 红马 | `red_ma` | 8 |
| 红炮 | `red_pao` | 7 |
| 红相 | `red_xiang` | 6 |

## 二、运动逻辑（strategy.py 状态机）

### 2.1 状态流转

```
SEARCH_GOAL ──找到球门并居中──► SEARCH_PIECE ──找到棋子──► ALIGN
     ▲                              │                        │
     │                              │ 没棋子                 │ 棋子居中
     │                              ▼                        ▼
     │                          (小角度转)               PUSH
     │                                                        │
     │                                                        │ 进球/太近
     └──────────── SCORE ◄────────────────────────────────────┘
                  (停车→倒车→回搜索)
```

### 2.2 各状态说明

| 状态 | 行为 | 退出条件 |
|------|------|---------|
| `SEARCH_GOAL` | 找到球门→转向使其居中；没找到→原地 45° 步进旋转扫描 | 球门中心 x 偏差 < 死区 |
| `SEARCH_PIECE` | 找到棋子→OCR 识别分值→选最高分目标；没找到→小角度转 | 有棋子被选中 |
| `ALIGN` | 保持目标棋子居中，左右微调转向 | 棋子中心 x 偏差 < 死区 |
| `PUSH` | 棋子居中则小步前进；偏离则先修正方向 | 棋子与球门重叠 / 棋子面积过大（太近） |
| `SCORE` | 停车 → 等 200ms → 倒车 60mm → 回 SEARCH_GOAL | 倒车 1.5s 后 |

### 2.3 非阻塞机制

- **去掉了所有 `wait_done` 阻塞调用**，发完指令立即返回，下一帧靠视觉反馈判断是否到位
- 指令冷却 `_cmd_interval = 300ms`：两次发指令间隔 ≥ 300ms，避免刷屏 ESP32
- `SCORE` 状态用分阶段计时（0=停车 / 1=等倒车 / 2=倒车中），不阻塞

### 2.4 指令下发（uart_comm.py）

通过 UART 115200 向 ESP32 发文本指令：

| 指令 | 格式 | 说明 |
|------|------|------|
| MOVE | `MOVE,<距离mm>,<速度%>` | 前进（负=后退） |
| TURN | `TURN,<角度°>,<速度%>` | 原地转向（正=右转） |
| STOP | `STOP` | 立即停止 |

## 三、目标优先级

### 3.1 当前优先级（有 OCR 模板时）

```
1. 分值最高的棋子（帅/将 10分 > 车 9分 > 马 8分 > ... > 兵/卒 1分）
2. 同分时选最居中的棋子
```

### 3.2 无 OCR 模板时（回退策略）

```
1. 选最居中的棋子（所有棋子等价）
```

### 3.3 后续可扩展的优先级

- 距离优先：优先选离球门近的棋子（减少推棋路程）
- 可达性优先：避开被对方棋子/挡板挡住的棋子
- 时间优先：比赛后期加快节奏

## 四、后续需要你做的事

### 🔴 高优先级（影响核心功能）

#### 1. 制作棋子字符模板图（让识字生效）
当前 `vision_ocr.py` 因无模板已自动回退。要让"优先推高分棋子"生效，需要：

1. 用手机拍每个棋子的清晰正面照（光线均匀）
2. 裁出汉字区域，转灰度，存为 `.pgm`
3. 放到 K230 的 `/sdcard/templates/` 目录，命名：
   - `red_shuai.pgm`（红帅）、`red_che.pgm`（红车）...
   - `black_jiang.pgm`（黑将）、`black_zu.pgm`（黑卒）...
4. 共 14 个模板

> 制作模板的 Python 脚本可找我要，能批量处理手机照片。

#### 2. 校准颜色阈值（赛场光线现场校准）
`config.py` 中的 `RED_THRESHOLD`、`BLACK_THRESHOLD`、`GOAL_THRESHOLD` 是占位值，必须在赛场用 CanMV IDE 的 LAB 滑块校准，否则识别不稳定。

#### 3. 确认赛题棋子分值表
当前 `PIECE_VALUES` 是象棋惯例值，需对照赛题官方分值表修改。

### 🟡 中优先级（稳定性）

#### 4. 进球判定逻辑
赛题要求"棋子整体进入球门区"，当前 `_is_goal_overlap` 用矩形重叠比例 > 0.5，需改为"棋子外接矩形完全包含在球门区域内"。前提：确认球门区范围。

#### 5. 对方棋子处理
当前只识别己方颜色，忽略对方棋子。需确认赛题是否允许推对方棋子、是否需要避障。

#### 6. IMU 航向漂移
推多枚棋子后航迹推算累积误差大，可利用球门做绝对航向参考定期回正。

### 🟢 低优先级（优化）

#### 7. 模板匹配精度不足时上 KPU CNN
若赛场光照变化大导致模板匹配不准，可训练 14 分类 CNN 模型，用 K230 的 KPU 加速推理（`vision_ocr.py` 末尾有说明）。

#### 8. 比赛时间管理
确认比赛总时长后，可在最后阶段加快节奏（减小 `_cmd_interval`、增大 `MOVE_STEP_MM`）。

#### 9. 对方车辆避障
确认是否需要主动避让对方车辆。

## 五、调试信息说明

画面左上角显示状态字符串 + FPS，例如：

```
ROTATING_SCAN FPS:29.1
FOUND_PIECE type=red_shuai val=10
TURN_TO_GOAL err=120
PUSH area=5200
```

| 关键词 | 含义 |
|--------|------|
| `ROTATING_SCAN` | 没找到球门，原地旋转扫描 |
| `TURN_TO_GOAL` | 球门已找到，转向居中 |
| `GOAL_CENTERED` | 球门已居中 |
| `FOUND_PIECE` | 找到棋子，括号内是识别类型和分值 |
| `ALIGN` | 对准棋子中 |
| `PIECE_ALIGNED` | 棋子已居中 |
| `PUSH` | 推进中，显示棋子面积 |
| `GOAL_OVERLAP` | 判定进球 |
| `SCORE_*` | 进球后停车/倒车流程 |
